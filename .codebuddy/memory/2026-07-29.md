### 背景

### 方法
- 位置: `open-os/src/chromium-browser/src/`
- 策略: `git clone --depth=1` 主仓库 + 手动克隆 DEPS 核心依赖
- depot_tools (gclient) 因 Python 依赖问题（需要 3.11+，系统 3.9）无法使用

- `boringssl.googlesource.com` 和 `dawn.googlesource.com` 完全被阻断
- boringssl 从 GitHub 官方镜像 `github.com/google/boringssl` 克隆成功

## OPENOS 首次启动系统 (openos-setup)

### 背景
openos-overlay 此前只有 theme + meta 包，缺少首次启动初始化。ChromiumOS 原有的 OOBE/chromeos_startup 仍走 Google 流程。需要 OPENOS 自己的首次启动脚本替代。

### 创建内容
**新包**: `chromeos-base/openos-setup-1.0.0`（位于 `openos-overlay/chromeos-base/openos-setup/`）

**文件结构**:
- `openos-setup-1.0.0.ebuild` — 安装脚本 + Upstart job
- `files/openos-first-boot.sh` — 首次启动初始化脚本
- `files/openos-first-boot.conf` — Upstart job 定义

**首次启动脚本执行的任务**（按顺序）:
1. **跳过 OOBE**: 创建 `/home/chronos/.oobe_completed` 标志，跳过 Google 设置向导
2. **系统身份**: 修复 stateful 分区中的 lsb-release 残留 Google 引用；设置默认 hostname
3. **OPT 包管理器**: 创建 `/etc/opt/opt-repos.conf` 系统级配置（openos-community + debian-bookworm 镜像源）；创建 chronos 用户缓存目录
4. **F-Droid**: 如果安装了 F-Droid privileged extension，修正权限
5. **Google 残留清理**: 删除 stateful 分区中残留的 Google 账户状态和 metrics-consent
6. **开发者默认值**: 生成 SSH host keys

**Upstart 集成**:
- 在 `boot-services` milestone 后触发
- 幂等：通过 `/mnt/stateful_partition/.openos_boot_completed` 标志确保只运行一次
- 依赖 `openos-meta` 已更新，自动拉入 openos-setup
